# 术语词典库：给纪要生成注入一份「权威写法对照表」

v1.4 的主题不是「加一个词典功能」，而是把会议纪要里的一类错字从根上收掉。这类错字有一个共同
来源：纪要生成那一步，模型拿到转写稿后，遇到专有名词、人名、医学术语，只能靠内部知识猜——
转写稿写对的地方它照抄，转写稿写错的地方它跟着错，猜的地方还会凭空写出新的错字。

这份文档记录搭词典库时沉淀的设计决策。它们大多不是「词典」特有的，而是任何「给模型输出
纠错、并且让纠错能力持续积累」的场景都会遇到的。

## 错字有两个来源，词典治的是后半段

先把根因拆开。一段录音到纪要，错字会出现在两个环节：

- **转写环节**：ASR 把语音转成文字。同音字（「岳总 / 月总 / 玉老师」发音相同）、低频专有名词、
  字母类术语，都是这一环的错字高发区。这一环的惯用解法是热词表，但热词有硬伤——塞多了会
  「假注入」（把无关词硬塞进转写，PoC 里「项目甲/项目乙」被塞进无关会议五六处），而同音字
  在发音层面本就无解，热词救不了。
- **纪要环节**：LLM 读转写稿写纪要。这一环的错字来源是「没有权威写法可依」，模型只能猜。

词典库治的是后半段。理由很朴素：给 LLM 注入一份「正确写法 + 常见错写」对照表，副作用是零——
它只影响生成结果，不污染转写稿；而且 LLM 有上下文理解能力，能纠转写环节救不了的同音字（看到
「树立协会」能根据上下文判成「数理协会」）。所以主战场放在纪要生成环节，不是再堆一层热词。

## 设计决策

**1. 快照契约：应用写、转写侧只读，两进程不漂移。** 词典的事实源放在应用侧的 SQLite（应用
负责管理界面、diff 反写），转写侧的派单进程需要这份词典来注入 prompt。两个独立进程，如果
转写侧直接读应用侧的数据库，就要跟着应用的 schema 迁移一起改，这是跨进程契约漂移。解法是
中间放一个 JSON 快照文件：应用在词典任何变更后原子重写（临时文件 + `os.replace`），转写侧
只读这个文件、格式不符就返回空列表不报错。契约从「一套数据库 schema」降成「一个 JSON 文件的
字段」，漂移面小得多。教训通用：跨进程共享数据，用文件契约比共享数据库更稳。

**2. diff 反写：把人工更正变成词典的自动积累。** 词典能不能「一劳永逸」，关键不在建表，在
积累机制。如果每次都要手工维护，词典就是个死文件。真正的闭环是：用户编辑纪要时把错字改成
正确写法，系统对比新旧 markdown 的 diff，捕获「替换」操作，写进待确认队列，人工确认后把错写
并进正确写法的别名。判断标准：**词典的规模应该随使用增长，而不是靠一次性的种子导入**。

过滤规则是这个机制的质量命门，要同时守住两头——不漏明显错字、不误抓正常编辑。抓替换块只认
2–8 字的短片段（错字更正几乎都发生在词级）；满足「编辑距离很小」或「新词已是已知正确写法」
才算疑似更正；排除整段重写、纯标点、纯数字。字符级 diff 的固有粒度是词根（「树立协会 →
数理协会」会捕获成「树立 → 数理」而非整词），确认环节靠上下文片段兜底，整词粒度要分词器，
留作后续。

**3. 排序要服务注入上限，不是字母序。** 注入 prompt 有 50 条上限，词典会越积越多，所以
「谁进前 50」决定了纠错质量。一开始按字母序排，立刻翻车：ADHD、CRF、EDC 这类几乎不会写错的
英文缩写排在前面，把「李总」「随访」这些真正容易写错的人名术语挤出了注入表。修法是把排序
交给纠错价值：**人名 > 含中文的词 > 纯英文缩写**。判断标准不是「字典序好不好看」，而是
「截断后剩下的是不是最需要纠错的」。

**4. 项目词用强特征词匹配，过滤弱特征。** 两层分域——通用词（人名、通用术语）全量注入，
项目词按项目隔离。难点是自动派单时并不知道这场会属于哪个项目，只能靠转写稿反推：命中某个
项目 scope 下的词，就判定这场会是该项目的会，注入该项目词。这里同样有「假注入」的翻版：
子串匹配里「代表」「专家」「看板」这类 2 字高频通用词，在任何会议都出现，误把它们当成项目
信号，会把无关项目词挤进注入表（占掉本来该给通用词的 50 条名额）。修法是匹配只用长度 ≥3
的强特征词，过滤掉 2 字弱特征词。误命中的代价大于漏命中——漏了项目词只是少纠几个错，误了
会把通用词挤掉。宁可漏，不可误。

**5. 同音字靠上下文，不靠热词。** 这是第 0 节「治后半段」的推论。ASR 对同音字从机制上无解
（发音一样，热词也无从下手），但 LLM 有上下文。所以词典的注入对象是纪要生成的 LLM，不是
转写引擎。想清楚「哪一环能治这个错」，比「把词典塞进越多环节越好」更值钱——塞进转写环节
反而会假注入。

## 两层分域

- **通用词**：人名、公司名、通用术语——跨项目都会出现，全量注入。
- **项目词**：某项目专属的术语——只在「转写稿命中该项目强特征词」时注入，避免跨项目串词。

分域的目的不是「分得细」，而是「不该出现的词别出现」。
